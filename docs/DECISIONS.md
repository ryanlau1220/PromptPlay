# Decisions and open work

- PCC uses the official NEAR fungible-token implementation. The issuer is restricted. A separate pre-funded faucet account holds a limited supply; the server only receives that dedicated account's key, never a player's wallet key. It reserves a claim before transfer and keeps uncertain results pending.
- The single-round game names both accounts at creation. Choices are 0 rock, 1 paper, 2 scissors. Each commitment is SHA-256 over `PromptPlay:RPS:v1`, the contract account and player account each prefixed by a little-endian u32 byte length, the match ID as little-endian u64, round 1 as little-endian u32, one choice byte and a 32-byte random secret. Base64 encodes the hash and secret for calls. Browser and sandbox vectors are independently checked. Secrets stay in browser storage until reveal; losing that storage can forfeit a match.
- The 0.01 NEAR creation deposit funds contract storage. The game and treasury have PCC storage registration. A CLI match and an isolated two-browser test-wallet match completed on Testnet. A real third-party browser wallet and all timeout cases still need end-to-end verification. Contracts have not been audited.
- Room WebSockets carry resync hints only. Clients fetch authoritative match state from NEAR and also poll; messages cannot settle funds or determine outcomes.
- Allowance accounting uses Bun's SQLite binding and immediate transactions. Authenticated direct transfers are matched against finalized Testnet receipts and intent-specific memos. Crediting is idempotent and atomic with intent completion. A controlled on-chain transfer was verified in an isolated local database, including a replay check; it did not use inference.
- Five PCC buys one demo gateway unit; balances and limits use millionths of a unit. `MICROS_PER_UNIT` defines the operator-funded maximum cost of a unit in USD micros. Model prices and limits are operator-configured, and activated economy settings are frozen in the database to prevent silent changes to prior commitments. The project cap limits issued plus pending units as well as request spending. Gateway startup checks that one demo unit covers the conservative maximum reservation for the default request. Outstanding or expired intents remain reserved until reconciled; uncertain inference requests also retain their reservation.
- NEAR AI Cloud at `https://cloud-api.near.ai/v1` and `zai-org/GLM-5.1-FP8` are defaults, not verified access or model availability. Funding and permission for the PCC gateway are unresolved. On 6 November 2026 the [public model catalog](https://near.ai/models) listed GLM 5.3 Flash; the proposed GLM 5.1 ID was not confirmed in that catalog. The provider model list must confirm the configured ID. [Model pricing](https://near.ai/models/z-ai/glm-5.3-flash) and the [pricing page](https://near.ai/pricing) showed different input prices, so do not freeze rates without confirming the applicable current price. Live inference and new redemptions require explicit live, authorization and funding flags plus a key, an explicit Testnet wallet allowlist and verified pricing/limits. The mock is clearly labeled and never represents a real provider response.
- The gateway supports non-streaming and streamed chat completions with function tool calls. OpenCode 1.18.21 read a local file through a real Nebius model after a finalized 5 PCC Testnet payment in an isolated operator-only gateway; usage settled. This does not prove compatibility with all clients, advanced OpenAI features, or authorization for public access. Public real-money wagering, provider-native credit transfers and cross-chain bridging remain unsupported.
- Keep the deployment single-instance with one durable SQLite database. Local and Compose servers must not operate the same faucet concurrently with separate databases. Remaining work includes third-party wallet verification, realistic sandbox timeouts, authorized real inference with metering, final deployment/demo evidence and submission.

- Nebius Token Factory is configured locally through the existing OpenAI-compatible provider as a temporary alternative. Its model catalog and a direct `Qwen/Qwen3-30B-A3B-Instruct-2507` request succeeded on 6 November 2026. This does not establish that third-party PCC redemption is authorized or funded; the live gate remains off pending applicable terms, pricing and account funding confirmation.

- On 6 November 2026, an isolated, operator-only local test used a finalized 5 PCC Testnet transfer (`HnJCfVUQjcNkjQsCdqYfkzCYFWCQjD5JnqUooBVfRuDn`), verified replay idempotency, and sent a real Nebius request through the gateway. Provider usage was 17 input and 6 output tokens; the test allowance decreased from 1,000,000 to 999,971 microunits using temporary test rates. This did not establish provider authorization for third-party gateway use or verify actual billing rates; public redemption stays disabled.

- Bun 1.3.10 is the JavaScript package manager, runtime and test runner for both apps. The server relies on Bun SQLite; Vite runs with Bun using `--bun`. The root workspace has one committed Bun lockfile and container builds use the pinned Bun image.

- Root Bun workspaces provide shared install and task commands for both apps and the Rust contracts. Turborepo is not used: two independent app packages and the contract build order do not currently justify another task runner.

- Audit on 6 November 2026 found that inference throttling was per key rather than per wallet; the limiter now counts all keys for the same account. A changed match ID no longer shows actions for the previous match while the new chain query is pending. Payment attempts are reserved atomically in the server database before opening the wallet, and the browser also records the attempt locally. This prevents another attempt through PromptPlay across devices; wallet rejections and uncertain outcomes require operator reconciliation. Older pending intents created before attempt tracking need manual review, and transfers sent outside PromptPlay cannot be prevented.
- The inference spending cap assumes provider pricing and maximum model context are configured conservatively. Since usage is checked after the upstream request, a provider that accepts more tokens than the configured context or adds unmetered charges can exceed the reservation. An enforceable provider-side cap or independently verified model limits and pricing are required before live operation.

- Streamed inference forwards provider events incrementally, requests a final usage report and settles only after a complete stream with valid usage. A disconnect, provider error or missing usage leaves the full reservation in place for reconciliation. Nebius sends cumulative usage on intermediate chunks; only its final usage event is used for settlement.

- The operator-only PCC-to-OpenCode test used Testnet transfer `2jJQrZkWHHyGY8C35DSeoPDSCDxGQXYA5QnKvzXbNC9X`, credited it once, and used Nebius streaming and a file-read tool. Three requests settled and the allowance fell from 1,000,000 to 994,336 microunits at temporary test rates. The live public redemption gate remains disabled pending applicable provider terms and verified pricing.
